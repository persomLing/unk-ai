# 智能补读与接口读取

日期：2026-11-05。适用于当前原生 JavaScript、Vite、Chrome Manifest V3 扩展。

## 已接入的用户行为

模型选择放在全局顶栏，普通问答和页面操作共用。开启“基于当前页”后，输入框底部集中显示页面操作、阅读强度和本站接口开关。页面开关仍决定本轮能否自动读取网页；关闭时不因问题复杂、连续追问或用户语气而重新开启。页面操作 Agent 不使用本次新增策略，其模式下隐藏阅读强度和接口开关。

阅读强度使用自定义菜单，当前选项有明确选中状态；支持方向键、Home/End、Tab、Esc 和点击外部关闭。“接口”直接点击切换，不需要先展开一个设置面板。悬停或键盘聚焦时显示本站状态与读取范围；设置正在读取或保存时禁用操作。失败或结果超时显示“未确认”，再次点击先核对实际状态，确认后才允许下一次切换。

底部右侧的“会话整理”使用 32px 叠层图标，悬停或键盘聚焦时显示估算容量，达到 75%/90% 时显示对应预警点。点击仍打开原有整理详情面板，已用/剩余比例、Token 估算、摘要与页面资料均保留，面板内可以执行“立即整理”。本次只调整入口呈现，不改变容量估算、压缩、输出预留或自动整理规则。

“＋”附件菜单只保留“上传图片”和“文档”，继续支持粘贴图片或截图；“当前页截图”和“框选区域”入口及对应入口调用已移除。普通问答的自动视觉、页面图表选择和 Agent 内部截图仍沿已有权限、目标与取消边界运行。保留的截图/裁剪辅助及历史测试不代表当前菜单仍提供手动框选。

| 选择 | 行为 |
| --- | --- |
| 自动（默认） | 先获取当前正文，检查资料缺口，必要时追加一次页面结构读取；明确规则在本地处理，灰色情况才请求模型判断 |
| 基础 | 使用已有页面读取路径，不自动追加智能补读；用户明确要求的必要能力仍须单独满足，不能假装完成 |
| 深入 | 当前正文之后补充页面结构；失败显示为本轮错误，不用普通正文冒充成功深读 |
| 接口开关 | 按 HTTP/HTTPS origin 单独保存允许状态，默认关闭；开启设置本身不启动监听，只有后续任务需要时才短暂使用 |

强度选择保留在当前侧栏，不覆盖已有页面开关偏好。接口设置是独立的本地站点授权，切换站点会重新核对。读取设置和保存设置均有时限；尚未确认或保存超时时，不发布“已允许”的提交快照，可以重新核对设置。已发起的存储写入可能稍后完成，停止等待不等于撤销设置写入。

## 根据资料缺口补读

`adaptive-reading.js` 返回结构化评估，不生成主回复。判断使用当前问题、已读页面及提交时固定的近期历史。正文截断、表格行覆盖不足、控件状态未知、目标尚未定位等属于证据缺口；问题长或复杂本身不要求增加页面访问。

同一页面近期相关问题中出现事实纠错，会提高核验优先级，并把来源、单位、计算需要重新核对的说明加入上下文。历史只取有界片段，按页面来源和话题相关性筛选；“说简单点”“换种解释”等风格要求以及单纯强硬语气不直接开启深读。这是有界的纠错信号判断，不能保证正确理解所有自然语言反馈。

灰色判断经 ModelGateway 的 `reading-decision` 用途执行，使用本轮冻结配置，最多等待 8 秒。模型只能返回有限的补读建议；页面内容作为不可信资料输入，不允许借页面指令扩大目标或权限。模型窗口不足、判断失败或无有效建议时保留缺口，不默认增加访问。

智能判断与结构补读共用最多 16 秒，每轮最多追加一次深读；已有可用深读结果时不重复附加调试器。补读固定 `tabId`、完整 URL 和文档身份，并设置 `lazyLoad: false`，不会自动滚动、点击、输入或刷新原页。结构读取与接口等待还受补充资料 adapter 的剩余时间预算约束，达到上限即结束等待。

自动选择的可选补读失败可保留当前正文，但记录未取得结构、超时或没有新资料等缺口。用户明确要求的深读失败会阻断本轮；取消、页面身份变化和权限拒绝不会作为普通可选失败吞掉。截图仍沿现有视觉能力执行，建议读取截图不等于已经取得图片。

## 接口读取的实际范围

本次仅接入普通问答。只有本轮需要接口证据、提交时允许使用接口且后台重新确认本站授权后，才建立绑定任务的监听会话。

监听针对开始以后、固定主文档产生的同源 Fetch/XHR，且响应声明为 JSON 类型。它读取浏览器实际收到的响应，不主动调用接口，也不读取请求头或请求正文。

| 限制 | 当前值 |
| --- | --- |
| 普通问答采集窗口 | 3 秒，连接与消息等待另有有界截止 |
| 后台会话默认 / 硬上限 | 30 秒 / 60 秒；不是普通问答默认监听时长 |
| 保留响应数量 | 最多 6 条 |
| 单响应原始大小 | 最多 64 KiB |
| 单条可保留正文 | 最多 6000 字符 |
| 合计可保留正文 | 最多 16000 字符，进入模型时继续受上下文预算限制 |

页面在提问前已经完成的接口请求通常无法补抓；跨源 API、非 JSON 响应、其他文档的响应也不属于当前范围。没有匹配响应时保留“未取得接口资料”的状态。用户明确要求接口读取却未授权或未取得可用响应时，本轮显示缺口或失败，不以普通 DOM 正文假装完成抓包。

不会为了获取数据自动刷新页面、翻页、重放请求或提交表单。网络读取尚未成为 Agent 工具，也不具备后台无人值守持续监听能力。

## 同页接口资料复用

`supplemental-reading.js` 只缓存过滤后的 `networkReading`，不缓存基础正文、深度结构或补读判断。每轮仍沿原路径读取当前正文，然后比较页面证据。缓存位于当前侧栏实例的内存 Map，最多 4 项，成功采集完成后的有效期为 5 分钟；命中不会延长有效期。最多保留 8 个会话/标签页观察代次，防止旧任务迟到写入覆盖新观察。

复用同时要求：提交时固定的会话 ID、`tabId`、完整 URL 和 `documentId` 一致；本轮基础 DOM 正文、表格和配置语义内容一致；问题与已有接口资料相关；原采集结果可用且未截断。普通相关追问可以使用缓存，不要求每次再次写出“读取接口”；无关的普通问答不会删除有效缓存，也不会自动带入旧接口资料。缺少明确文档身份或会话范围时不启用缓存。

每次命中前仍通过后台重新核验页面目标和本站授权。页面变化、授权关闭、超时到期、资料缺口或截断、明确要求最新数据或重新采集时不复用；有必要时重新监听，失败仍报告本轮真实结果，不用旧缓存冒充新采集。取消的旧任务、迟到结果和被新任务替代的采集不能写入新缓存。切换会话不共享条目，队列等待回到原会话后才使用原范围，关闭侧栏即释放缓存。

命中结果使用 `networkReading.status: "reused"`，并增加 `cache: { version: 1, capturedAt, reusedAt, expiresAt }`。命中时三个时间均为 ISO 字符串：`capturedAt` 表示该批可识别的最早原采集时间，`reusedAt` 表示本轮复用时间，`expiresAt` 保留原到期时间。首次采集记录也可带这份缓存元数据，此时 `reusedAt` 为空字符串。各响应自己的 `capturedAt` 不变。界面和模型上下文说明“复用已采集资料，未重新监听”，不能把复用时间说成接口最新返回时间。

已保存会话的 `pageContext` 可能包含当时的过滤后接口资料，但不会用于恢复运行缓存。侧栏重开、扩展重启后必须重新采集；此机制也不构成跨会话记忆或完整网络日志。

主题和字段覆盖使用保守的本地规则，可能放弃本可复用的结果。后台数据更新若尚未反映到 DOM，不能仅靠页面比较检测到；需要最新结果时应明确要求更新或重新采集，沿新监听处理。

## 归属、权限与资料处理

后台仅接受可信扩展调用，监听会话绑定侧栏端口、任务标识、取消标识和页面身份。关闭侧栏、停止、导航或同 URL 重载、授权撤销、调试器断开及到期都会结束监听，迟到事件不得转写到新任务。

深读、截图与网络监听共用按标签页独占的调试器协调器。已有读取占用时不会再次附加并拆掉别人的连接；连接或释放超时的真实操作仍被隔离，直至其实际结束。Chrome DevTools 或其他扩展占用调试器时，仍可能无法读取。

响应先在本地进行字段过滤、常见凭据、邮箱和手机号等模式脱敏以及大小裁剪，再进入模型上下文。**脱敏不能保证识别所有业务敏感内容。** 过滤后的资料仍属于网页来源的不可信数据，不作为系统指令或操作许可。原始响应仅用于当前有界处理，不保存完整网络日志。

每轮 `readingOptions` 使用 version 1，固定强度与 `allowNetwork`，随入队、撤回后再提交和重试遵循各自提交边界；原位重试沿用原回合选项并重新校验授权。没有新字段的旧回合默认基础读取且不允许接口，不因升级扩大范围。

`readingAssessment` 保存有限的结果、原因和缺口。脱敏裁剪后的接口资料随当前会话 `pageContext` 保存，历史回合只保留来源与结果小元数据，不保存每轮完整响应快照。`networkReadingPermissions` 在扩展本地存储中使用 version 1；损坏或不兼容记录明确报错，不静默重置历史授权。

## 生产模块

| 模块 | 职责 |
| --- | --- |
| `features/page-reading/reading-controls.js` | 强度自定义菜单、接口单击开关和悬停说明；只发布已核验的授权状态 |
| `features/page-reading/adaptive-reading.js` | 本地缺口规则、灰色模型判断、一次结构补读 |
| `features/page-reading/supplemental-reading.js` | 正文准备之后组合智能补读与接口证据，按会话和页面维护有界内存缓存、复用前重新核验授权，不持有主回复提交入口 |
| `features/page-reading/network-reading-cache.js` | 接口缓存的范围、语义内容和主题匹配、固定有效期、限量、失效与复用时间记录 |
| `features/page-reading/network-reading-client.js` | 侧栏端口、任务绑定、采集窗口与退出清理 |
| `background/network-reading-service.js` | 后台权限、页面身份、调试器独占与网络事件生命周期 |
| `utils/network-reading.js` | 版本化站点授权和响应过滤预算 |
| `utils/network-reading-context.js` | 来源检查、接口结果归一化及模型预算序列化 |
| `utils/reading-options.js`、`utils/reading-assessment.js` | 每轮固定选项、历史兼容、评估白名单与缺口说明 |

以上 `features/` 路径相对 `src/sidepanel/`，其他路径相对 `src/`。ConversationService 仅传递固定参数和 `cacheScope: { conversationId }`，再调用补充资料 adapter；发送、队列、停止、原位重试和唯一主回复继续使用现有运行链路。缓存由 feature 管理，编排层不注入其他会话的 `previousPage`。业务模型调用仍全部经 ModelGateway，不另建一套流式生成流程。
