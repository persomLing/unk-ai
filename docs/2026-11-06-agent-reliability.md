# Agent 多步骤任务可靠性

## 故障与实施顺序

2026-11-06 的诊断包包含一个任务、19 次完成的模型决策：13 次选择读取页面/区域，6 次选择下拉项。选择均在后台元素签名校验阶段被拒，决策累计约 206.6 秒，最终耗尽步数。

分三批实施：底层校验与失败恢复；子目标、状态核验与受控参考图上传；在既有设置内按进展调整预算和一次有界重规划。

## 已接入生产的行为

- 后台与 scanner 使用固定字段的语义签名，Chrome 重排返回对象键不会造成误报；真实控件、字段、跳转和表单目标变化仍阻断。
- 观察提供主文档 ID、原生 select 当前项与有界选项、checked/pressed 状态和文件输入能力。选择事件后有界等待更新并核验，回滚返回 `ERR_ACTION_NOT_APPLIED`。
- `task-progress.js` 保存 version 1 的任务、标签、完整 URL、文档和执行代次。读取不会清零操作失败；同目标/动作/错误阶段第二次失败触发一次重规划，第三次停止。
- 多步骤写操作先建立 3–8 项计划。模型标记 completed 不等于核验成功；状态、动作效果由程序检查。普通正文读取不能证明上传、填写或生成完成。纯阅读保留既有正文及章节完成检查。
- `verify_state` 重新观察并唯一匹配目标，核对选项、勾选/按压/展开状态或文件数量，避免反复切换已满足目标的控件。截断字段不能作为完整等值证据。
- 旧状态被后续写入或明确不匹配推翻时，撤销旧证据。异文档结果不核验当前控件；未核验动作保留等待后续观察，不自动重放。

仍由 `agent-slot.js` 持有同一主回复与执行所有者，经 ModelGateway 决策，后台继续仲裁权限、串行化、目标和幂等。普通问答的发送、重试及流解析未因本次功能改写。

## 参考图上传

`upload_reference_image` 只接受后台登记的 `reference-1` 等编号及当前元素 ID，不接受任意路径、URL 或模型提供的字节。图片来自本任务用户消息，最多 3 张、合计 8 MiB，核验类型、预算及文件头。后台仅内存登记；暂停/结束撤销，恢复从原任务重新登记。

支持可见原生文件输入，以及浏览器原生关联可见 label 的隐藏输入；后者只允许专用上传动作。任意脚本按钮、无法关联的拖拽区、目录上传和缺少 File/DataTransfer 的页面需要接管。每次上传沿用确认、任务许可、当前文档与快照校验。

成功只表示真实 FileList 已核对。网站可能立即发送请求，服务器收件、预览、处理和生成结果还需后续证据。事件发出后结果不明则停止，不自动重传；同动作 ID 不重复派发。

## 预算与恢复

初始步数窗口最多 12 步，用户设置始终是硬上限。只有新增且去重的真实进展可延长窗口，不延长时间。重规划和修改计划本身不算进展。

持续没有进展时给一次重规划机会。当前模型支持视觉时可补一次有界截图，截图前后核对快照、完整 URL、文档、活动标签和任务归属；取消后的迟到截图不会进入模型。只有无进展且当前模型已启用思考时，才在新 run 提高一次已有思考档位；不改变模型、服务或凭据。确定性执行器拒绝不会触发思考升级。

仍逐动作执行和核验。批量执行多动作、任意站点接口重放、自动切换模型供应商和关闭侧栏后持续运行不在本次交付范围。
