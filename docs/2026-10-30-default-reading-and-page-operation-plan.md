# 下一轮计划：默认理解页面，可选操作页面

状态：已在 0.17.6 实施。实现与验证记录见 [0.17.6 发布说明](2026-10-30-default-reading-release.md)。下面保留原方案；上一轮 0.17.5 交付包继续保留。

## 产品方向

普通提问应具备按需理解当前页、查目录、读取相关文章的能力。“找 MCP 章节并总结”不要求用户先选择“阅读研究”或“页面操作”。页面开关继续决定本轮能否读取网页。

“页面操作”保留为用户明确开启的扩展能力，用于点击、输入、导航、滚动等交互。模型应获得足够的页面区域、滚动容器、链接目标和动作反馈，理解应该在哪里操作。不能把普通阅读失败自动升级为页面控制。

这借鉴的是读取与交互的能力分工；竞品云端调度的实际实现仍不能由本地安装包确定。

## 两张图对应的问题

| 场景 | 当前代码的缺口 | 下一轮预期 |
| --- | --- | --- |
| 普通提问“找到 MCP 章节并总结” | 站内研究仍依赖手动开关；目录发现还要求当前正文先成功 | 默认按问题和真实目录按需补读，不开启 Agent、不移动标签 |

| 相同提问分别用普通对话、页面操作发送 | 用户消息已有 agentTask，但不显示；去重/自动重试没有完整固定模式 | 操作提问显示“页面操作”标记，模式贯穿发送、去重、重试和历史 |

以上是代码可确认的缺口；截图没有附对应任务的完整动作日志，因此不把某一缺口认定为这次失败的唯一原因。

## 1. 默认按需阅读

发送时一次性固定目标标签、完整 URL、文档身份、页面开关和本轮模式。轻量目录捕获与正文读取解耦，避免当前页正文超时就直接放弃整个问题。

决策依据来自用户问题与实际目录，采用本地规则，不新增一次模型分类请求：

- “总结这页”“只解释选中段落”：保持当前页/选区范围。
- “找 MCP 章节”“本站哪里讲 MCP”：匹配真实目录，提供对应章节位置与链接。
- “找到 MCP 章节并总结”“对比 Agent 和 MCP”：明确匹配后读取相关章正文，再回答。
- 普通闲聊、仅处理附件、直接问模型、页面开关关闭：不发起额外站内读取。
- 无明确目录命中：说明已有资料范围，不按弱关键词随意抓取其他页面。

匹配优先级为明确章节编号、完整术语或缩写、多关键词共同命中。保留原始链接用于显示，同时按实际文档地址分组：Docsify 的 `#/chapter?id=section` 是某章内的小节，`#/another-chapter` 才是另一章。目录采集分别给其他章节和当前小节分配名额，不能让前面几十个小节挤掉后面的第 20 章。

当前正文读取失败，但目录和第 20 章正文成功时，可以继续基于第 20 章回答；只有目录成功时，只能说“目录列有该章节”，不能总结未读正文。来源数据应允许“定位页面存在、当前正文不可用、相关文章已成功”的状态，当前页仅作为定位依据时不计入已读正文来源。

重用现有同站公开 GET、最多目录一次与正文三篇、额外正文 24000 字符和按来源分配 token 的限制。正文、目录和补读共用总截止时间及取消信号，不让先后超时累加成长期卡住。

输入框恢复简单主流程：当前页开关、输入框、附件/模型、可选“页面操作”。普通站内补读不再以手动“阅读研究”作为前置条件；是否保留手动扩大研究范围的入口属于后续增强，不阻塞本轮。

## 2. 让操作模式理解页面结构

补充受预算约束的结构信息，不发送整棵 DOM：

- 区域：导航目录、主正文、工具栏等角色、名称和粗略位置。
- 滚动容器：观察 ID、所属区域、可滚动方向、当前位置、最大位置、可视尺寸。
- 交互元素：所属区域/容器、真实 href、是否在容器可见区、当前项和展开状态。
- 导航目标：当前文档、章内锚点、另一章节；目标标题与已读取正文的来源。

例：模型需要知道“左侧教程目录可以继续向下滚动；第 20 章 MCP 是另一个文档”，而非只看到混在一起的一组链接名称。DOM 中已有章节 href 时可以直接据此定位；只有确实需要操作菜单时才滚动相应容器。没有挂载的虚拟列表条目不能伪造。

尽量复用现有 `scroll_page(elementId)`，为真实滚动容器登记可选择 ID；按目标容器的高/宽计算位移。工具返回目标和前后位置，明确区分已移动、已到边界、没有移动、目标不可滚动。不能把对一个链接调用 scrollBy 当作成功滚动。

重复动作判断包含目标容器及方向。动作反馈比较相应容器、展开状态、当前章节和正文，不把时钟等无关变化算作成功。读到当前页 MCP 概述不等于完成“阅读第 20 章”；完成判断需核对目标章节和成功读取的来源。

实现需要同步 scanner、后台局部/全局 ID 映射、schema 白名单及反馈逻辑。安全语义与易变布局字段应分离，避免新增 scrollTop/bounds 后破坏执行前的元素签名校验。原有 task/epoch、URL/documentId、暂停、接管、取消保护继续保留。

模型输入应明确本轮能力：普通对话只能依据实际提供的阅读结果回答，不能声称操作过页面；操作模式才提供真实可用的交互工具。仅增加一句提示词不足以补齐这些观察与执行信息。

## 3. 消息标记与错误卡片

用户消息中的“页面操作”小标记取自发送时固定并保存的模式，不读取当前按钮状态。普通消息保持简洁。历史已有 agentTask 的记录可以直接显示标记；没有证据的旧消息不推测其模式。

同一句话以不同模式发送应视为不同请求。模式必须进入自动重试上下文与重复发送指纹；Agent 重新开始仍生成新任务，普通失败问题不能因切换模式而被误判为旧问题的普通重试。

错误展示统一为短原因与可选详情：

> 未能打开第 20 章，已停止重复操作。当前只读到本页的 MCP 概述。  展开详情

- 默认文字最多两行，长内容省略。
- 展开显示完整错误/诊断，按钮可收起；正文结果不再复制进错误区。
- 长详情限高并可独立滚动，展开状态与深度思考分开。
- 手动展开和滚动后保持阅读位置，不强制跳到消息底部。
- 旧历史只有长 errorMessage 时保留原文作为详情，默认折叠；无需批量改写历史文件。
- 标记、错误详情和 UI 展开状态不作为新的模型上下文反复发送。

## 实施顺序与验收

1. 先固定每轮模式，完成用户消息标记、去重/重试隔离和两行错误卡片。
2. 接入普通对话的默认按需阅读，拆开目录与正文依赖，建立章/节与来源状态。
3. 补齐操作模式的区域和滚动容器观察、实际滚动反馈与章节完成检查。
4. 用截图站点和独立测试页面验证，全部完成后再发布下一版。

必需验收：

- 不选择研究或操作模式，提问“找 MCP 章节并总结”，读到真正第 20 章，原标签和滚动位置不变。
- 当前页也有 MCP 小节时不冒充第 20 章；当前正文超时而目录/目标章成功时仍能回答。
- 左侧目录初始只露出前几章，操作模式能选择目录容器、滚到第 20 章并验证目标正文；中央正文不会因选错容器而滚动。
- 目录超过 80 个链接、父容器裁切、目录已到底、选错滚动目标、章节已经展开时均能得到准确反馈，不循环点击。
- 普通失败后切到操作模式发送同文，出现正确标记并启动新任务，不掉进普通重试。
- 长错误默认两行、可展开收起，旧历史兼容，思考与详情可分别滚动。
- 关闭页面开关、排队后关闭、切页后重试、同 URL 刷新及取消后迟到结果均不串来源。
- 小模型窗口下保留各已采用来源的代表正文与 URL，不因新增布局和目录信息突破预算。

本计划不承诺全网搜索、长期知识库或任意后台浏览；先完成默认页面理解与可选页面交互这两个清楚的方向。
