# 0.17.5：站内阅读研究与页面操作优化

本轮围绕“帮我找到 Agent 章节并总结”的使用场景增加第二条能力路径，保留现有页面操作 Agent。

## 使用方式

- 普通对话：不选择能力，页面开关沿用原来的显示与默认开启规则。
- 阅读研究：打开页面开关，选择“阅读研究”，输入问题。根据当前站点真实目录读取相关文章并展示来源。
- 页面操作：选择“页面操作”，在站点授权后执行任务。读取正文使用独立工具；切换标签或手动操作仍按原规则暂停。

研究不操作用户标签，最多补充三篇、合计 24000 字符正文；不提供全网搜索。页面来源固定在发送时，关闭开关后不会继续启动排队的网页读取；重试刷新原页与相关文章，不沿用旧正文。动态/登录/不支持的站点会说明没有读到额外资料。

## 实现与费用

目录与路由捕获在主文档执行只读函数。Docsify 根据明确配置把 hash 章节映射到 Markdown，兼容目标站翻译插件增加的单通配 alias；其余未知规则不猜测。公开文章请求使用同源 GET、omit credentials、禁止跳转和有界时间/字节预算。正文及网页指令均以不可信资料处理。

本地选链接没有额外模型分类调用。研究正文会增加模型输入，但先经过现有预算，超限时按来源分配正文空间而非让首篇独占。会话只存一份当前研究正文，历史消息只存来源等小元数据；容量超限显示“待裁剪”，清楚区分裁剪前估算与实际发送量/账单。

Agent 增加 `read_page(query?)`，后台同时核对 task/epoch、snapshot、完整 URL 与 documentId，20 秒超时可取消。任务最多保留三份/18000 字符，模型请求进一步计入工具 schema、1200 token 输出与估算余量。基础指令已超容量时直接报错，不发送不可能成功的请求。动作后的新观察反馈可见变化；重复未变时提示读正文或换方法，并在继续重复时暂停。完成直接展示 `finish_task.summary`，不再无条件发第二次总结请求。

Agent 的停止/失败只提供“重新开始任务”，回到最初页后创建新任务，重新观察并授权，不经过普通聊天的 regenerate；历史暂停按钮必须匹配当前 taskId。任务准备时取消或授权失败仍保留对应用户提问，避免出现没有提问的任务结果。

## 验证证据

- `node --test tests/*.test.js`：550/550 通过，日志 `output/research-tests.log`。
- `npm run build`：成功，输出版本 0.17.5；现有 chunk 大小与 theme-boot 提示仍保留。
- 实际公开站 `didilili.github.io/ai-agents-from-zero/`：用独立浏览器加载截图中的第 1-3 章，捕获 119 个导航链接及运行后的 Docsify 配置。生产构建流程实际获取第 21 章 Agent、第 26 章 LangGraph 和一篇相关实战章节，原标签 URL 与滚动位置未变化。
- 浏览器中的 Chrome API 与模型使用替身，未调用用户配置的模型、未读取用户登录信息或操作其真实标签。验证涵盖关闭开关后禁止重试、开启后刷新研究、停止后丢弃迟到目录、Agent 正文读取后直接完成，以及重启产生新 taskId。此验证不证明每家真实模型都能正确决定下一步。
- 该 Agent 场景共一次观察、一次正文读取和两次模型决策；未调用普通聊天或追加总结模型。
- 320/420/760 px 输入框无横向溢出；来源列表、预算提示与暗色模式已检查。
