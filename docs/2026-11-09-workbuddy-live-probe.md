# WorkBuddy2API 实际接口验证 · 2026-11-09

原失败回合在显式“重新回答”后成功，本次经授权测试对应的真实中转服务，公开记录省略部署地址和账户配置。验证使用项目现有 ModelGateway、流式解析器及普通回答工具循环，通过真实 HTTP 请求完成；没有修改中转配置或重启服务。

## 测试条件

- 测试模型由该服务 `/v1/models` 确认可用；部署专用模型标识不在公开记录中保留。
- 认证信息仅保存在测试进程内，未写入脚本、日志或本文；公开记录不包含凭据来源。
- 思考参数省略，交由中转默认策略；`max_tokens=8192`。未确认与扩展当时的全部参数、服务路由或配额相同。
- 四项测试串行执行。两次追问使用同一段既有对话进行真实重放；匿名化问题摘要为“为已有配置代码添加说明”，未携带原请求的思考内容。
- 保存的结果只有状态、时间、字符/字节数量、工具名称和结束标记，不保存回答正文、思考文本或密钥。

## 结果

| 测试 | 总耗时 | 观察到的结果 |
| --- | ---: | --- |
| 一句话解释 YAML，无工具 | 13.98 秒 | 成功；约 12.90 秒才开始收到流数据，13.43 秒收到正文 |
| 配置代码注释追问（匿名化摘要），第 1 次 | 9.71 秒 | 成功；首正文约 2.52 秒，模型自行选择直接回答，未调用工具 |
| 同一对话和参数，第 2 次 | 12.26 秒 | 成功；首正文约 5.91 秒，模型自行选择直接回答，未调用工具 |
| 模型搜索 YAML 官方规范、读取来源、回答 | 10.66 秒 | 成功；原生 `tool_calls` → `/v1/web_search` → 模型 → `/v1/web_fetch` → 模型最终回答 |

最后一项实际包含三个模型请求、一次搜索和一次正文读取。两个工具轮分别返回 `finish_reason=tool_calls`，最终回答返回 `finish_reason=stop`；六个流式模型请求全部收到 `[DONE]`。HTTP 请求均返回 200。工具链的搜索约 1.15 秒，正文抓取约 4.75 秒。

两次相同追问的思考输出分别为 272、2066 字符，说明默认思考下生成量存在变化。第一项短问题的首包等待比另外几项明显更长；单凭客户端计时不能区分中转排队、上游首包计算或网络等待。

## 可以与不能得出的结论

现有中转能够与项目当前的 Chat Completions 流式协议、原生工具分片、工具结果回送及搜索/抓取接口协同工作。原来仅收到少量思考、约 46.8 秒后没有完成标记的故障未在本次复现；实际重试成功和这四项结果支持其为偶发异常，而非必然不兼容，但尚不能定位中转内部或上游的责任层。

这不是稳定性或吞吐量压测，不证明以后不会断流；也没有实测 Chrome 扩展 UI、全部服务账户及 MV3 生命周期。缺少完成标记仍应保留可见失败，不能仅凭已有思考或连接关闭就当作成功。原来的显式重新回答仍沿用回合替换规则。
