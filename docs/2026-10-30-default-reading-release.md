# 0.17.6：默认按需阅读与页面操作优化

普通提问可以按问题查当前站点的真实目录、补读相关章节，不再要求先选“阅读研究”。“页面操作”保留为主动选择的能力，用于点击、输入、滚动及导航。

## 本轮改动

- 发送、排队时固定模式、标签、完整 URL 及文档身份。重试在等待配置前固定目标，新任务重新核对文档；普通队列项不会因当前模式按钮改变而变成操作任务，也不会因自动重试清空后续队列。
- 正文与目录分别读取，共用 20 秒截止和取消信号。当前页正文失败时，可继续基于成功读取的章节回答；只知道目录位置不能冒充读过正文。
- 区分 Docsify 的独立章节与章内 `?id=` 小节，目录配额不会被前面的本页小节耗尽。明确章节编号限定对应章节，完整 MCP 术语不会拆成“模型”“上下文”而抓取无关页面。
- 新消息保存版本化阅读策略及选定来源；重试不扩大已规划的章节范围。旧普通消息维持单页重试。页面关闭、仅附件、直接提问模型及简单闲聊不触发额外站内读取。
- Agent 观察提供导航/正文区域、真实滚动容器、粗略位置、所属容器、当前项与展开状态。滚动按目标容器尺寸执行，返回实际位移、边界、无移动或不可滚动；背景时钟变化不再算目标动作成功。
- 对可确认的独立章节目标，完成前核对已读取正文来源，避免用本页 MCP 概述冒充第 20 章。安全元数据和易变布局分开，维持原任务、文档、暂停和接管校验。
- 用户的操作提问显示“页面操作”标记；错误默认两行，支持展开/收起和独立滚动。旧错误全文重复正文时只保留一份正文，错误展开与思考展开相互独立。

## 成本和边界

阅读决策在本地执行，不增加模型分类调用。轻量页面身份检查只读取 URL/文档标识，不把页面正文持续发给模型。额外网页仍限制为三篇、合计 24000 字符，并接受上下文预算裁剪；只有真正补读时才增加相应输入 token。历史消息只保存策略、来源等小元数据，不逐轮复制网页正文。现有追问建议和历史压缩仍可能各自调用模型。

Agent 最多提供 80 个观察目标，其中真实滚动容器最多 8 个，继续使用已有模型窗口和工具预算。DOM 中没有挂载的虚拟列表内容无法凭空发现；复杂动态路由、需要登录的页面及全网搜索不属于本轮默认阅读能力。

- `node --test tests/*.test.js`：**614/614 通过**。覆盖取消、迟到回调、来源隔离、同 URL 刷新、旧重试、混合模式队列、按来源裁剪、滚动反馈、章节完成校验和错误 UI。日志：`output/default-reading-full-tests.log`。
- `npm run build`：成功，版本 **0.17.6**。原有 theme-boot 经典脚本提示与大 chunk 提示仍存在，没有新增构建失败。日志：`output/default-reading-build.log`。
- 真实公开教程站：从截图中的第 1-3 章出发，普通输入“找到mcp章节并总结一下”仅补读真正的 `20-MCP模型上下文协议.md`。真实公开正文进入模型请求，原标签 URL 与滚动位置不变。
- 完整输入“找到第20章MCP模型上下文协议并总结”同样只抓第 20 章；正文失败时只把成功章节列为已读来源。关闭页面后禁止读取/重试，取消后迟到的目录结果不会启动模型。
- 最终构建烟雾验证：同 URL 刷新后人工重试，正文与目录使用重试捕获的新 documentId，章节来源集合不扩大。
- 真实浏览器里的独立目录夹具：100 章、父容器裁切、平滑滚动样式和页眉时钟。扫描器选中目录容器、滚到第 20 章、点击后主正文更新，window 始终保持 `(0,0)`；普通链接返回 `ERR_NOT_SCROLLABLE`，底部返回 `at_boundary`。
- 生产侧栏：错误折叠高 37px（两行），展开限高 280px 并可独立滚动；收起重置预览位置。320/420/760px 输入框无横向溢出，亮暗主题已目视检查。同一句普通失败提问切换操作模式后确实启动新任务并显示标记。

浏览器测试使用隔离实例，模型及 Chrome 扩展接口用替身；公开章节通过真实 GET 读取，滚动夹具使用实际 DOM 执行器。未请求用户配置的模型，因而这些结果验证资料、约束与界面流程，不代表所有模型的决策和总结质量。
