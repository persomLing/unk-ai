# UU 生图 Agent 停滞定位与透明控件修复

本次使用的匿名诊断摘要包含前一项任务和两次后续任务。后续任务分别用时 44.672 秒和 53.559 秒，均在第 5 步进入恢复、第 7 步因无执行进展停止，未触及 12/20 步上限。最后一项任务七次模型决策用时 49.279 秒，占总时间 92.01%；只有一次约 1.1 秒的等待动作，没有点击、输入、选择或上传请求。每轮仍带有原参考图，所以这次不是重启丢图。

## 原页面证据

对 `https://uuapi.io/image-studio` 做了只读 DOM/可访问性检查，核对实际控件结构。

- GIF 开关是正确关联的原生 checkbox 与可见 label；input 为 1×1、opacity=0、pointer-events=none，label 为 296×49。旧扫描器会丢掉真实 checkbox。
- 上传区是 DIV 中覆盖可见区域的原生 file input，带“上传参考图（最多 6 张）”aria-label；input 为 294×50、opacity=0、pointer-events=auto，父区为 296×52。它没有关联 label，旧扫描器也会丢掉上传控件。
- 提示词是有正确 label 的普通 textarea；局部视觉目标选择原先没有 textarea/textbox 提示，泛化计划标题还会替代原目标。多相关控件同分时直接放弃裁剪，且目标为空就提前标记恢复已使用，日志没有留下跳过原因。

日志本身不保存具体 DOM 或计划正文，不能单凭日志断言模型为何选择某条计划。本次原站点检查验证了扫描器与真实控件结构不兼容；没有在原站点输入、上传或提交生成请求。

在实际原生侧栏的隔离回归中，又确认选到目标后原生截图报“需要 `<all_urls>` 或 `activeTab`”。从侧栏直接恢复原标签页并不等同于用户点击扩展工具栏授予临时截图权限。这是实际截图入口差异，不能用裁剪单元测试证明它已经可用。

## 实现边界

`agent-scanner.js` 保留真实 input 元素身份，为正确关联的透明 checkbox/radio 使用可见 label 的几何与命中检查，点击关联 label 并读取原 input 的 checked 状态。透明文件输入仅在可见、具名、命中测试有效的父上传区内获得 `viaOverlay` 支持；隐藏、过小、越出父区、无法命中、被遮挡或禁用的控件仍拒绝。文件控件继续只允许专用确认上传，不能通用点击或输入。映射变化进入前后台的语义签名复核，透明父区身份与可见语义在赋值前再次检查；赋值后的正常计数及预览变化不会被当成失败。Scanner 版本提升至 10 以替换页面中的旧实例。

`selectAgentVisualTarget` 返回结构化目标或明确缺失/歧义原因。泛计划回退原始用户目标，支持 GIF/动图与提示词输入框；同一小区域内的不同相关控件可共享现有裁剪。同类重复或分散的等价控件仍返回歧义，不使用 body 或任意全页裁剪。图像只用于观察，后续写动作仍由模型选择当前 elementId，经过既有后台权限、任务、页面和幂等边界。

`agent-slot.js` 仅在实际尝试局部观察时消耗一次自动恢复机会；目标缺失时在原有恢复预算内允许后续具体计划重新选择。成功、跳过及捕获失败均进入可见记录、下一轮反馈与诊断，权限/页面变化仍立即暂停。`task_progress` 向决策暴露写任务、执行证据相关性、无进展轮数及最多三轮恢复剩余量。停止诊断保存真实 `no-progress`、结果不明、时间或步数原因。

`agent-service.js` 仅在原生截图明确缺少临时截图授权、且请求固定完整 URL 与主文档时，复用已有 `withPageDebugger` 通道捕获视口 JPEG。没有新增权限或全页截图。整个后台截图最多三秒，包括原生尝试、调试器连接、捕获及核验；停止后不启动迟到捕获。截图前后及连接调试器后均复核控制许可、任务、活动标签、完整 URL、文档、快照、视口与滚动。显式拒绝不会进入回退，调试器忙则明确失败；原生浏览器的调试提示条若改变视口，也会拒绝旧裁剪坐标。

`decision-context.js` 为写任务增加独立的 3000 字符结构化区域摘要预算，保留近期正文与来源、有限数值示例及覆盖/省略说明。完整任务资料不改，纯阅读保留原摘要规则。诊断增加区域摘要字符和来源数量，仍不保存正文、图片或输入值。减少输入与空转轮数并不能保证具体供应商响应提速。

## 验证

行为回归先重现透明控件不可观察、恢复机会提前消耗、失败反馈缺失和诊断原因丢失，再验证最小修复。覆盖映射失效、遮挡、禁用、页面/许可变化、取消、迟到结果、来源、预算和唯一终态。

浏览器回归使用隔离 Chrome、实际构建扩展和原生侧栏，页面复刻上述 DOM，模型使用本地可控响应。它验证 DOM 执行及确认上传链；不代表真实模型一定能作出正确决策，也不代表 UU API 服务器生成或所有 MV3 生命周期已实测。

最终 `npm run check` 1574 项测试通过并构建 `dist`，记录在 `output/diagnostics/2026-11-06-agent-transparent-controls-check.log`。实际扩展回归入口为 `tests/browser/agent-transparent-controls-native-extension.js`，结果为 `output/playwright/agent-transparent-controls-native-validation.json`：六次受控决策核验模型、切换 GIF、输入及逐次确认上传，原 PNG 字节进入 FileList、input/change 各一次；另一场景四轮计划/读取后，第五请求携带原 PNG 与一个 640×296 局部 JPEG，来源和候选元素固定，页面没有写动作。

浏览器回归期间还确认同版本扩展未重新加载时，旧 service worker 会继续使用旧截图实现。显式重新加载扩展后，同一无临时截图授权的隔离配置通过两个场景。用户应用新 `dist` 后须在扩展管理页重新加载 UNK AI，再重新打开侧栏；仅重试旧侧栏中的任务不会装入新代码。本次在原 UU API 页面只读检查，没有提交收费生成，也没有用真实模型完成该站点生图任务。
