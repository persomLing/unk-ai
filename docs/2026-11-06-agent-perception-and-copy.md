# Agent 页面感知与复制命中修复

2026-11-06，本次针对写任务反复读取却不执行，以及提问复制按钮被右侧轮次导航挡住的问题作了最小修复。Agent 仍通过侧栏中的既有执行循环、ModelGateway 和后台受控动作边界运行；普通问答、停止、重试及唯一主回复路径保持原接口。

当日后续新日志另定位到透明 GIF/上传控件被漏扫、自动视觉目标过窄与失败静默问题；后续实现和当前验证范围以[透明控件修复](2026-11-06-agent-transparent-controls.md)为准。本文件保留第一轮证据及当时实现范围。

## 日志所揭示的问题

本次使用的匿名诊断摘要记录了一项持续 192.569 秒的任务。18 次模型请求累计 186.120 秒，占任务时间约 96.65%；17 次有效决策是 6 次改计划、3 次读取正文、6 次读取区域、1 次滚动和1次状态核验。没有点击、上传或填写的执行记录，已核验目标一直是 0/5，最后 HTTP 200 响应被协议判断为空结果，任务失败。

实际读取、观察和滚动分别约 0.954、0.396 和 0.326 秒。慢点主要是无进展的模型决策轮数，而非 DOM 扫描耗时。诊断不含正文、截图或供应商原始响应，无法仅凭相同字符数证明两段正文完全相同，也无法确定供应商为何返回空结果。本次不把局部视觉功能等同于所有任务都会更快。

## 写任务的进展与恢复

- 多步骤写任务连续 4 轮没有真实执行进展时，进入一次有界恢复；恢复后最多再 3 轮仍没有推进则停止。
- 新正文、计划修改、一般状态观察和滚动不重置写任务的无进展计数，也不能换取扩步。已核验的有效写动作、对应目标状态或确定性确认的必要子目标才能计入执行进展。
- 模型声明计划完成不等于执行证据；同一份证据不重复发放进展。纯阅读任务保留原有正文、章节完成和预算规则。
- 状态核验只关联同任务、标签页、完整 URL 和文档中的成功写操作；SPA 保留同一控件也不能把旧页面的操作算作新页面进展。
- 操作失败仍按动作、目标和失败阶段累计；同类第二次失败给一次调整机会，第三次停止。读取成功不能抹掉失败。
- 结果不明的页面动作优先停止并等待核对；不自动重放提交或上传。扩步仍受用户设置的硬上限约束，不延长任务时间。
- Version 1 检查点新增可选写任务策略字段，保留旧计划、动作和失败记录；旧记录中的阅读进展不作为写任务的新扩步信用，异任务、异目标或未知版本不继承运行许可。

## 已接入的局部视觉观察

`inspect_visual` 只接受当前 DOM 观察中的 `elementId`。显式调用及无进展恢复先重新观察页面，按稳定目标唯一重匹配，再通过原任务受控捕获并裁剪控件附近的画面。当前只支持可见主页面元素；不把 iframe 坐标映射到主页面截图。

每任务最多 3 次局部观察，同一稳定目标只尝试一次。输出为 JPEG，最长边 960 像素、最大 512 KiB；整个局部观察最多等待 3 秒。元数据包含任务、标签页、完整 URL、文档、快照、视口、裁剪原点、缩放和最多 24 个候选元素 ID。页面、视口、目标或所有者变化会拒绝结果；停止后的迟到捕获或裁剪不能启动请求、覆盖新任务或清除其运行状态。

局部图片进入下一次已有 `agent-decision` 请求，不另设主回复或额外视觉判断模型请求。图片及图中文字仍是不可信页面资料。后续选择、点击、输入和上传只使用当前元素 ID，继续经过后台权限、任务许可、目标和幂等检查；本次没有添加任意坐标点击。非视觉模型提示接管；没有唯一可见候选时不猜测随机截图目标。

自动恢复截图属于可选资料：额外图片超过当前模型上下文预算时，省略这张自动图片，保留当前 DOM、目标和原参考图片后重新检查预算。用户提供的参考图或模型显式请求的局部图不足以装入预算时，仍明确失败；控制、站点许可或页面身份失效立即暂停，不作为普通截图失败吞掉。

## 动作请求正文与诊断

`decision-context.js` 按实际正文及完整页面/文档身份去重；仅改变 query 或采集时间不表示正文变化。写任务的每次动作决策正文节选合计最多 3000 字符，每份最多 1500 字符，附来源和截断说明。完整已读记录仍按原任务预算保留，纯阅读请求不套用这一动作节选限制。

诊断新增输入字符、估算 Token、图片数量及字节数、读取数量和被移除的读取数量，用于区分大输入、重复读取、视觉观察和模型等待。日志不保存提示词、图片、输入值或密钥；Token 仍是本地估算，不能等同于供应商计费。

## 提问复制按钮与轮次导航

原先即使气泡到按钮的悬停路径已接通，右侧 `turn-navigator` 的透明区域仍能截获鼠标；窄屏下刻度展开区域也可能覆盖复制按钮。现在透明导航容器和刻度展开装饰不接收点击，真实刻度保留悬停预览、键盘聚焦及点击跳转。提问操作区继续横跨气泡下方预留空间，显隐不改变消息和后续回答的位置。

在 Windows 的隔离 Chromium 配置中加载实际已构建的 `dist` 扩展，验证了 320、544 和 650px 宽度：长提问、PNG 附件提问、窄提问、与刻度纵向对齐及刻度展开状态均可通过慢速鼠标移动和原始按下/抬起复制。每次实际点击只写入剪贴板一次，原生剪贴板回读与显示提问一致；键盘复制及导航预览、跳转也通过。比较原生剪贴板时仅归一化 Windows 的换行格式。

可复用回归为 `tests/browser/user-message-copy-extension.js`，验证记录为 `output/playwright/user-copy-extension-validation.json`；Vite 预览的鼠标、键盘和触屏路径另外由 `tests/browser/user-message-actions.js` 覆盖。浏览器回归不由 `npm test` 自动运行。

## 验证边界

自动化回归包括 `agent-task-progress`、`agent-decision-context`、`agent-visual-observation`、`agent-decision-loop`、Agent 生命周期和诊断关联测试，覆盖来源固定、重复截图、无视觉模型、无候选、迟到结果、正文预算、HTTP 200 空结果和唯一终态。整体交付仍使用 `npm run check`。

局部裁剪另在隔离的真实浏览器中直接运行生产 Canvas 裁剪代码，普通 DPI 和 2 倍 DPI 下的中心、大控件、边缘及小视口共 8 例通过。验证 JPEG 解码、最长边和字节预算、裁剪来源尺寸、目标色标及坐标梯度像素映射；回归入口为 `tests/browser/agent-visual-crop.js`，记录为 `output/playwright/agent-visual-crop-validation.json`。这验证本地图像映射，不等同于真实模型辨认控件成功。

实际 `dist` 扩展原生剪贴板验证已完成。本地替身和合成页面不能代表用户原网站的模型菜单、上传流程和生成服务全部成功，也不代表全部模型供应商或完整 MV3 生命周期已实测；本次未在用户原网站提交生成或消费请求。页面控件可访问性、视觉模型质量和服务响应时间仍会影响速度与成功率。
