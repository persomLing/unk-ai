# UNK-AI 首版设计文档

## 1. 产品目标

UNK-AI 首版是一个基于 Chrome Manifest V3 的纯前端 AI 阅读助手，提供侧边栏对话、当前网页总结、会话保存和 Markdown 导出。

首版遵循以下原则：

- **零自建后端**：浏览器直接连接用户配置的大模型服务，不经过第三方中转服务器。
- **默认本地保存**：API 配置和会话保存在 `chrome.storage.local`。
- **按需发送网页内容**：仅在用户发起网页总结或网页问答时，将提取内容发送给所选模型服务商。
- **优先保证基础体验**：首版不实现浏览器自动操作，不以 Agent 架构增加基础功能的复杂度。

## 2. 首版范围

### 包含

- OpenAI 兼容的 Chat Completions 接口配置与流式对话。
- 新建、切换、重命名和删除会话。
- 停止生成、重新生成和复制回答。
- 当前网页正文提取、一键总结和基于正文的追问。
- Markdown、代码块和数学公式渲染。
- 会话自动保存到 `chrome.storage.local`。
- 手动导出单个会话或网页摘要为 Markdown 文件。

### 不包含

- Browser Agent、CDP、自动点击和自动输入。
- 自动跨标签页、跨域或后台持续执行任务。
- 外部目录自动同步、同步队列和崩溃恢复。
- 截图、多模态、多标签页对比。
- 插件市场、账号系统和云端同步。

以上能力可以在后续独立设计中扩展，不影响首版的数据格式。

## 3. 页面与交互

### 3.1 侧边栏

侧边栏包含四个区域：

1. **顶部栏**：新建会话、历史会话和设置入口。
2. **网页工具栏**：显示当前页面标题，提供“总结当前网页”按钮。
3. **消息列表**：展示用户消息、模型回答、生成状态和错误信息。
4. **输入区**：文本输入、发送和停止生成按钮。

空状态直接提供“开始对话”和“总结当前网页”两个操作。网页不可读取时仍允许普通对话，并说明网页功能不可用的原因。

### 3.2 设置页

设置项包括：

- Endpoint URL：填写完整的 Chat Completions 地址，例如 `https://api.deepseek.com/chat/completions`，客户端不再自动拼接路径。
- API Key：本地模型允许留空，其余服务按服务商要求填写。
- 获取模型：使用 URL 和 API Key 读取 /models，以列表选择模型，并读取上下文长度、最大输出、思考与视觉能力。
- 上下文长度、最大输出、Temperature、思考开关和视觉能力；能力元数据可手动覆盖。
- 思考强度：使用服务商公布的 reasoning efforts，未声明时提供常用档位。
- “测试连接”：发送一条最小非流式请求，展示成功状态或可理解的错误。

不自动轮询模型服务，不在测试连接时发送网页内容。

### 3.3 历史会话

历史列表按最后更新时间倒序展示标题、时间和消息数量。删除会话需要二次确认；正在生成的会话不能删除，需先停止生成。

## 4. 技术架构

```text
SidePanel
  ├─ 对话与设置交互
  ├─ 直接调用 LLM API，持有 AbortController
  ├─ 渲染流式回答并保存会话
  └─ 请求当前标签页正文
              │
              ▼
Background Service Worker
  ├─ 打开侧边栏与快捷键处理
  └─ 转发一次性的正文提取请求
              │
              ▼
Content Script（按需注入）
  └─ 提取标题、URL 和正文，不常驻监听页面
```

### 职责约定

- **SidePanel**：首版对话请求的唯一执行者。关闭侧边栏可以中断正在生成的回答；已收到的部分内容正常保存，并标记为未完成。
- **Background**：仅处理扩展生命周期、侧边栏和页面通信，不维护对话状态或 Agent 状态机。
- **Content Script**：只执行按需提取，不读取输入框内容，不修改网页，不持续观察 DOM。
- **Options**：负责配置编辑；配置仍通过统一的本地配置模块读写。

首版不承诺关闭侧边栏后继续生成，也不使用端口或定时器保活。

## 5. 核心流程

### 5.1 流式对话

1. 用户发送消息，立即保存用户消息并创建生成中的助手消息。
2. SidePanel 使用当前会话的有限上下文调用模型接口。
3. 每收到一个文本增量就更新界面，并按合理间隔批量保存，避免每个 token 写一次存储。
4. 正常结束后保存完整回答和模型元信息。
5. 用户停止时调用 `AbortController.abort()`，保留已生成内容并标记 `stopped`。
6. 请求失败时保留用户消息和已有回答，展示错误并提供重试，不静默重复提交。

重新生成只针对最后一条助手回答，采用“保留原回答、追加新回答”的简单策略，不实现消息分支管理。

### 5.2 网页总结与追问

1. 用户点击“总结当前网页”，SidePanel 请求当前活动标签页。
2. Background 尝试向已有 Content Script 发消息；无响应时按需注入后重试一次。
3. Content Script 返回 `title`、`url`、`text` 和 `truncated`。
4. SidePanel 在界面中显示即将发送的网页标题和来源，再将正文加入总结请求。
5. 提取结果仅作为当前会话的网页上下文保存，后续追问复用，不重复抓取。
6. 页面 URL 或标题发生实质变化时，将旧上下文标记为来源页面，不自动替换成新页面。

网页正文属于不可信数据。系统提示必须明确：网页中的指令、所谓系统消息或要求泄露配置的内容均不得改变扩展行为。

### 5.3 手动导出

- 默认通过浏览器下载生成 `.md` 文件，无需持久目录授权。
- 文件名由日期、清理后的会话标题和短会话 ID 组成，避免意外覆盖。
- 导出包含标题、来源 URL、创建时间和完整消息；不包含 API Key 或其他设置。
- 后续若增加“导出到指定目录”，仅在用户点击导出时申请目录权限，不引入后台自动同步。

## 6. 数据模型

配置和会话分开存储。所有时间使用 ISO 8601 字符串，ID 使用 `crypto.randomUUID()`。

```ts
interface ProviderConfig {
  version: 1;
  endpointUrl: string;
  apiKey?: string;
  model: string;
  temperature?: number;
  maxTokens?: number;
}

interface PageContext {
  title: string;
  url: string;
  text: string;
  truncated: boolean;
  capturedAt: string;
}

interface Message {
  id: string;
  role: "user" | "assistant";
  content: string;
  status: "complete" | "streaming" | "stopped" | "error";
  createdAt: string;
  model?: string;
  errorMessage?: string;
}

interface Conversation {
  version: 1;
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  messages: Message[];
  pageContext?: PageContext;
}
```

存储采用一个会话索引加独立会话记录：

- `providerConfig`：模型配置。
- `conversationIndex`：ID、标题、更新时间和消息数量。
- `conversation:{id}`：完整会话。

会话更新时先写完整会话，再更新索引。首版不实现跨设备同步、文件格式迁移或外部文件反向导入。

## 7. API 与流式协议

首版只承诺兼容 OpenAI 风格的 `POST /chat/completions`：

```json
{
  "model": "用户配置的模型",
  "messages": [],
  "stream": true,
  "temperature": 0.7,
  "max_tokens": 2048
}
```

- 仅发送配置中非空的可选参数。
- SSE 按事件边界解析，支持跨网络分片、CRLF、注释行和结尾残余缓冲。
- 正常读取 `choices[0].delta.content`；遇到 `[DONE]` 结束。
- 推理模型的 `reasoning_content` 首版默认不展示、不写入对话上下文。
- HTTP 错误展示状态码和经过截断的服务端错误，不输出 Authorization 请求头。
- 请求必须支持取消和超时；超时只终止请求，不自动重试。

上下文采用简单预算：保留系统提示、网页上下文和最近若干条完整消息。超出字符预算时从最旧消息开始省略，并在请求层标注已省略；首版不实现自动摘要压缩或向量检索。

## 8. 正文提取

首版采用够用且可回退的提取策略：

1. 优先选择唯一的 `article` 或 `main`；没有合适容器时使用 `body`。
2. 基于原页面获取可见文本，排除脚本、样式、导航、页脚、表单和隐藏内容。
3. 保留标题与段落换行，不追求复杂正文密度评分。
4. 清理重复空行和空白，但保留代码块中的换行。
5. 默认最多提取 20,000 个字符；超限时保留开头和结尾，扣除省略提示所占预算，并返回 `truncated: true`。

如果提取文本过短，提示用户页面可能依赖登录、动态加载或不支持读取，允许复制文本后手动提问。首版不自动滚动页面，也不承诺覆盖所有网站。

## 9. 权限、安全与隐私

Manifest 只申请首版需要的权限：

- `sidePanel`：原生侧边栏。
- `storage`：配置和会话。
- `activeTab`、`scripting`：用户操作后读取当前标签页。
- `downloads`：使用浏览器下载导出 Markdown。
- `host_permissions`：仅用于用户配置的 API 地址；无法静态穷举时需在安装和设置界面说明原因。

安全要求：

- 不使用远程脚本、远程样式或动态执行远程代码。
- 模型输出先按纯文本解析 Markdown，再经过 HTML 消毒；禁止原始 HTML、脚本和危险链接协议。
- 代码高亮和数学公式库本地打包。
- 网页内容始终作为不可信引用材料传入模型，不能提升为系统指令。
- API Key 仅保存在本机浏览器存储中；界面明确说明本地存储并非系统级加密，不将 Key 写入日志、导出文件或错误信息。
- 不读取 `chrome://`、Chrome Web Store、扩展内部页面等受限页面。

## 10. 错误处理

- **未配置模型**：发送前跳转到设置并保留草稿。
- **网络或鉴权失败**：显示可重试错误，不清空当前会话。
- **生成中断**：保存部分内容并标记状态，不显示为完整回答。
- **页面不可访问**：保留普通对话能力，禁用网页操作并解释原因。
- **正文为空或过短**：允许重试，不发送空网页总结请求。
- **存储失败或空间不足**：保留内存中的当前会话，提示导出，并停止无意义的重复写入。
- **存储中存在 `streaming` 状态**：扩展重新打开时统一转为 `stopped`，不自动续接请求。

## 11. 验收标准

### 对话

- 配置有效服务后可以连续对话、停止生成和重新生成。
- 流式数据跨分片、带 CRLF 或最后一行没有换行时不丢内容。
- 刷新或重开侧边栏后，会话顺序和消息状态正确。
- 请求失败、取消和超时不会丢失已有消息或重复发送用户输入。

### 网页

- 普通文章页能够提取主要文本并生成带来源的总结。
- 导航较多、正文较短、动态加载和受限页面均有明确回退提示。
- 超过字符预算时输出不超过预算，且界面标明内容已截断。
- 网页中的指令文本不会改变扩展配置或触发额外行为。

### 存储与导出

- 新建、切换、重命名和删除会话后，索引与内容一致。
- 导出的 Markdown 不包含 API Key，标题和 URL 中的特殊字符不会破坏文件结构。
- 存储失败不会清空当前页面中的会话。

### 安全与兼容

- 模型返回脚本、事件属性或 `javascript:` 链接时不能执行。
- 未触发网页功能时不读取当前页面正文。
- 关闭侧边栏后没有残留网络请求或后台生成任务。

## 12. 后续扩展边界

后续功能按独立模块增加：

- **知识库导出**：在手动 Markdown 导出稳定后，再增加用户主动授权的指定目录保存。
- **多模态与多标签页**：单独定义用户选择范围、内容确认和上下文预算。
- **Browser Agent**：独立设计任务状态机、安全策略、元素定位和人工接管，不复用普通对话流程来隐式执行网页操作。

这些扩展不得要求首版提前引入 Agent 状态、CDP 控制器或后台保活机制。
