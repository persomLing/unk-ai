# 本地诊断日志与故障反馈

## 目标与边界

诊断应回答：哪个回合、哪个模型请求或页面动作，在什么阶段耗时或失败，失败前实际观察到了什么。错误卡片只是摘要，日志提供关联证据。日志不能证明模型服务内部的排队或思考状态，也不能从 DOM 输入成功推断业务接口已经提交成功。

日志默认开启，独立于“基于当前页”和“接口”开关；它记录插件执行过程，不开启页面抓包。不会默认持久化提问、回答、思考、网页文本、附件、输入值、Cookie、请求头、API Key、完整 URL 或原始异常栈。未知文本字段直接丢弃，错误消息只在内存分类。关联 ID 以本安装随机盐做 SHA-256；同一编号可跨模块匹配，无法直接当作原会话 ID 使用。

## 文件与保留

- 路径：已选本地数据目录下 `diagnostics/unk-ai-diagnostic-v1-YYYY-MM-DD-<批次ID>.json`。日期按北京时间，分片不可变。
- schema version 为 1；独立 IndexedDB 数据库 `unk-ai-diagnostics` 保存待写事件、批次和匿名关联，不变更会话文件及 outbox。未知较新版本报错，不自动重置。
- 保留北京时间今天及前 6 个自然日。只清理文件名、格式标记、版本、本安装 owner、批次、日期和事件校验均匹配的过期日志，不删除任意用户文件或其他安装的日志。
- 启动、记录和同步时维护保留期；扩展/浏览器关闭期间不运行。无法访问的旧目录要在恢复访问后才能清理。
- 每个事件绑定取得的原目录句柄；换目录不搬迁、不重定向待写。没有目录的事件保持未绑定，仅可从浏览器导出。
- 写入使用独立跨上下文锁和不可变文件名。写入超时保留待写批次；迟到 close 成功只能确认其自身批次，重试核验相同内容，不重复文件或覆盖新批次。没有锁时保留缓冲并显示状态。
- 缓冲默认最多 2000 条 / 2 MiB，批次最多 40 条；达到上限记录 dropped 数量。单个挂起 I/O 或观察器异常不阻塞主回答和动作。

## 事件链

每条记录有 `id / at / event / level / source / context / data / error`。标识存在 `context`，小型证据存在 `data`。不同源的同一动作可能各有一条开始/完成，这是侧栏发起与后台执行两个边界，不是重复执行。

回合只记录阶段切换，忽略逐 token 的重复阶段。`turn.phase` 的 `phase` 表示进入的新阶段，`previousPhase/previousPhaseDurationMs` 表示刚结束阶段及耗时；`turn.terminal` 的 `durationMs` 是最后阶段耗时，`elapsedMs` 是回合总耗时。模型请求/动作/读取事件的 `durationMs` 按各自开始边界计算。

| 范围 | 主要记录 | 可定位的信息 |
| --- | --- | --- |
| 普通对话 | `turn.started/bound/phase/terminal` | 准备、读取、检索、等待模型、思考、正文、最终状态；阶段耗时、总耗时、部分输出 |
| 页面读取 | `reading.started/completed/failed/cancelled` | 固定回合和目标文档、基础/补读阶段、正文数量、来源数量、权限/页面变化/超时 |
| 联网研究 | `research.*` 与模型用途 `research-decision/web-search/web-fetch` | 判断、搜索、抓取、整个研究阶段耗时；不是把等待都称为“模型思考” |
| 模型网关 | `model.request.*` | 冻结 run/request/purpose、整体开始/结束/取消/超时、辅助请求与主回答区分 |
| 模型传输 | `model.transport.*` | HTTP 状态、内容类型、首字节、首思考、首正文、分块/字节/事件数量、回退、协议/空输出/截断等固定原因 |
| 页面 Agent | `agent.task.* / agent.observe.* / agent.decision.* / agent.action.* / agent.input.stage` | 任务终止原因与累计错误数；权限、目标、快照、元素身份、安全、执行、输入校验阶段；同 actionId 的跨层证据 |
| 保存与运行环境 | `storage.* / runtime.*` | 当前会话保存状态、准备存储失败、前端未捕获错误分类；可保留本扩展 JS 文件名和行列以定位代码，不保存原始错误文本或堆栈 |

输入动作仅记录标签/角色/类型、是否连接、启用、只读、聚焦、预期/实际字符数和比较结果；不记录字符本身。检查是当次控件状态，不是业务成功回执。Agent 共享错误计数可能来自观察、决策、授权或动作，`error-limit` 不等于三次业务提交。

SSE 有真实首字节与解析统计；非流式 JSON 保留 `response.json()` 的既有路径，只记录响应头和 body 开始/结束，不把 JSON 解析完成时间伪称首字节。兼容回退带 attempt/reason，不新增重试策略。推荐问题和独立压缩的模型 run 显式绑定调用时的原会话身份；即使主回合已经结束、用户切换了对话，日志仍能归属原对话。这里新增的接口仅为固定诊断元数据，现有 core 无法从辅助 runId 推导所属对话；已先构造真实组合失败回归，再接入，不改变回复和终态路径。

## 用户反馈与导出

顶栏下载按钮提供“图片 / PDF”和“诊断日志”。正常对话也能导出本对话今天（北京时间）的诊断记录，生成中不禁用；没有可导出的问答时只禁用图片/PDF选项。两个诊断入口共用忙状态和导出器，点击前复核菜单所属会话，避免切换后错导；开始后沿既有固定归属完成导出。

错误消息下展示“导出今天的诊断日志”，固定点击时的对话 ID 与北京时间日期。设置 → 本地数据可导出当天全部对话并查看权限、待写、最近写入和丢失情况。两者共用有界导出，重复点击不会重复下载，释放 UI 后迟到收集结果不能启动下载。下载交给浏览器后由用户管理。

导出 JSON 包含 `format/version/appVersion/date/timezone/generatedAt/capabilities/scope/coverage/status/events/sharedEvents`。当前对话按 conversationId 及关联 run/task 匹配；关联可回看保留期内的绑定，跨午夜仍只导出所选日期事件。相关共享环境记录单列，最多 40 条，不混入其他会话正文。文件夹仅读取当前选中目录，同时合并浏览器仍暂存的事件；其他目录不会暗中遍历。

当日文件候选最多 600、读取最多 8 MiB / 5000 条事件，触顶标 `partial`；无关日期和普通文件不占当日候选预算，但仍受总时间预算。浏览器暂存可能追加部分事件。`coverage` 标示来源、记录起始时间、首末事件时间、缺失原因、关联/共享截断及数量；`status.dropped` 是全局累计计数，不代表当前会话确实丢了同样多条。

## 支持人员如何查

1. 先看版本、日期、范围和 `coverage/status`。`partial`、未绑定目录、权限不足、丢失或未关闭批次存在时，不推断没有记录的步骤没有发生。旧版本未启用日志的故障无法补录。
2. 找 `level:error` 和失败终态，按 conversationId → runId/taskId → requestId/actionId 关联；按 `at` 排时间线。先看最早的具体失败，再看后续停止摘要，避免把最终“错误达到上限”当根因。
3. 慢请求：找请求开始、headers、first-byte、first-reasoning、first-content 和结束。没有 headers 只说明扩展未拿到响应头；有 HTTP 429 说明服务限流；headers 后没有输出可能是等待/传输/协议问题，不能断言服务正在思考。
4. 动作失败：先看后台 `failureStage/error.code`；权限、页面/文档变化、快照失效、元素遮挡与输入失败是不同问题。输入发生后 `connected:false` 或 `valueMatched:false` 提供当时的控件证据，但不单凭它认定网站框架实现或兑换码有效性。
5. 若只有动作 started 而没有可信终态，结果保持未知；核对页面真实状态后再决定后续操作，不能凭日志自动重放可能提交的动作。
6. 请求用户补充大致时间、预期行为与必要的脱敏截图。服务端内部原因仍可能需要对应服务日志；本包不假装具有该证据。

## 验证范围

行为测试涵盖固定归属、跨午夜关联、目录切换、7 天清理、未知文件保护、读写/确认超时、重试幂等、日志异常隔离、敏感字段过滤、SSE/JSON 阶段、Agent 输入校验和导出取消/重复点击。浏览器 UI 核验使用合成失败记录，确认 360px 宽度展开、无横向溢出及明暗主题；另在独立测试站点用真实 IndexedDB、Web Lock、浏览器私有文件系统目录完成缓冲→写文件→当前对话导出，核验事件数、HTTP 429、匿名 ID 和过滤。私有文件系统验证不等于用户选择文件夹权限验证。没有真实兑换操作，也不代表所有站点、服务商、外部文件夹权限与 MV3 重启场景都已实测。
