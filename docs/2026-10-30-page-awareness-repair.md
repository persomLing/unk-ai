# 2026-10-30 页面感知与请求边界修复记录

本次修复围绕一个真实问题展开：用户读完 A 页，切到 B 页后继续询问当前页面（匿名化问题摘要），模型拿到了 B 页的数据，却认为没有新页面，并把之前针对 A 页的正确回答当成错误改正。检查同时发现正文隐私、异步页面身份、Agent 停止、保存和流式错误处理等边界问题。

本文描述修复后的代码行为，并分别标注代码推断、自动化验证和未完成的运行验证。当前模块位置见[模块地图](MODULE-MAP.md)。

## 1. 问题原因

对真实会话记录的匿名化复盘显示，上一轮来源是模型条目 A；下一轮提交针对当前页的追问约 236 毫秒后，全局页面上下文更新为模型条目 B。错误回答引用了 B 页的实际价格、成功率和延迟，所以问题并不是完全没有读到 B 页。

旧请求构造存在两个关联问题：

- 会话只保存一份全局当前页面，后来读取的 B 页替换了 A 页。
- 构造历史消息时丢弃了每轮来源信息，又把最新页面正文放在所有历史消息之前。

按保存记录和旧代码重建，关键消息顺序相当于：

```text
system
user: B 页正文
assistant: 上一轮针对 A 页的回答
user: [继续询问当前页面；匿名化问题摘要]
```

模型没有可靠的信息判断“上一轮是 A 页，本轮才换到 B 页”，容易把历史回答理解成对 B 页的错误解读。

这属于根据保存记录与请求代码进行的重建；没有当时的原始 HTTP 请求抓包，不能将重建称为精确的线上请求记录。

## 2. 页面感知与发送行为

修复后把“当前浏览器页面信息”和“本轮已经读取的正文”分开：

| 时机 | 实际行为 |
| --- | --- |
| 标签页切换、URL/标题更新、加载完成 | 更新当前页标题、网址、图标和可读状态 |
| 窗口重新获得焦点、侧栏重新可见 | 重新同步当前页信息 |
| 页面开关开启并发送普通问题 | 固定当前标签页，重新读取本轮正文；同 URL 也强制刷新 |
| 明确要求深度读取 | 在固定目标上进行深度读取和按需滚动补全 |
| 页面开关关闭 | 本轮不自动读取网页；主动附加的选区、图片和文件仍按消息内容处理 |
| 可读页面读取失败或身份变化 | 提示本轮读取失败，不静默沿用旧正文 |

页面切换和焦点事件只同步元数据，不持续读取、上传正文。普通发送也不再先让模型在当前页、旧页和直接回答之间自由决定；仓库源码分支由识别出的仓库 URL 和明确的源码问题触发。

页面状态提示现在说明“发送时读取当前页面”“页面已切换 · 发送时读取新页面”或“已关闭 · 本轮不读取网页”，避免把上一份阅读结果误显示成当前页已经读取的状态。

### 每轮来源和请求顺序

`turn-source.js` 保存本轮的 URL、标题、采集时间及可用的 `tabId`、`documentId`；`context.js` 保留历史消息的来源说明，并把当前正文放到当前用户问题旁边。正文与本轮来源不匹配时，不把另一个页面的正文作为该轮证据。

请求、读取和回复处理捕获所属会话、消息 ID 和取消信号；保存导致对象克隆后按 ID 找回对应回合，防止把完成状态写到已经失效的对象或其他会话。

**目前每轮保存的是来源元数据，不是完整网页快照。** 会话仍只有一份完整的当前 `pageContext`。重新生成旧回合时，如果旧正文已被替换，会说明原正文未保留；来源标签本身不能恢复旧正文。这是已知数据模型限制。

## 3. 正文隐私修复

生产内容脚本加载顺序包括 `aria-snapshot-bundle.js → extractor.js → content.js`。此前正文路径会调用第三方快照实现，其内部可能读取输入框的实时 `.value`，因此仅检查提取器自身的过滤规则不足以证明安全。

本次改动：

- 正文使用已有的受控文本收集逻辑，不再调用第三方 bundle 的输入值提取路径。
- 保留自有标题、表格、链接和表单标签结构。
- 排除输入框、文本域、`contenteditable`、实际可编辑节点及 textbox/searchbox/combobox 草稿。
- AX 深度读取排除可编辑节点及其后代，不回退使用节点输入值。

第三方 bundle 仍在扩展产物中加载，当前正文路径不再调用它。这个修复只针对自动正文提取；网页已经展示的文本、用户明确选择的内容和截图像素不是自动脱敏结果。

## 4. 页面身份与异步竞态

`page-target.js` 统一整理和验证目标。侧栏、读取插槽、后台提取、深度读取、自动视觉与截图沿用同一个目标，而不是在每个异步步骤重新选择“当前标签页”。

- 使用 `tabId`、预期 URL 和可获取的文档标识做前后校验。
- 同 URL 的文档重载也会使旧读取失效。
- 用户切到别的标签页不会让后台把新标签页的内容冒充为原目标。
- 自动视觉在模型预判前绑定来源；没有可靠标签页身份时不自动截图。
- 可见标签页截图回退要求原目标在截图前后都处于活动状态，否则丢弃结果。
- 脚本不可注入的 PDF 截图回退校验 CDP frame/loader 身份。
- 裁剪截图不再误标为整页；图表选择消息携带来源标签页和文档身份。

这些检查保证读取结果的归属，不保证网页在读取期间完全静止，也不等于所有第三方站点都已进行端到端验证。

## 5. Agent、保存、流式响应和界面

### Agent 执行边界

Agent 的模型请求和主循环仍在 `features/agent/agent-slot.js`，即侧栏文档上下文。后台承担执行许可、权限、安全与动作状态仲裁，本次没有把 LLM 循环迁移到 Service Worker。

后台执行代次使暂停、停止、接管和恢复前的旧动作失效；动作串行化并使用 `actionId` 记录避免重复执行。执行前后校验任务许可和页面状态，重启后的任务需要明确恢复。页面接管先通知后台暂停，再更新 UI；Agent 控制消息也检查扩展发送方边界。

这些措施阻止后续或尚未执行的旧动作，不能撤销已经发生的页面操作。关闭侧栏后的持续无人值守执行仍未实现。

### 本地会话保存

当前策略是 **IndexedDB outbox → 文件夹写入 → 按版本确认**：

1. 在 IndexedDB 事务中保存完整待写会话、版本和绑定的目录句柄。
2. 在文档上下文中使用 File System Access API 写入会话文件。
3. 仅确认本次版本；写盘失败保留记录并显示待同步状态。
4. 初始化或手动同步时重试；列表和加载优先合并待写的新版本。

会话绑定目录，切换当前目录不会重定向已有待同步会话。窗口内队列和可用的 Web Locks 协调写入。当前实现没有采用原 README 中描述的 `.tmp` 重命名方案；浏览器存储也不提供断电或清除用户数据后的绝对恢复保证。

### 上下文与流式响应

请求预算会预留输出空间，对旧历史和页面内容进行必要压缩/截断，并保留最新问题。所有 Token 数和阈值均为估算，不是精确 tokenizer 或计费统计。无法容纳的请求会报告限制，不通过丢弃最新问题来假装满足预算。

流式中途错误、异常结束和服务端错误被标记为错误，避免把半段回复当作完整成功。取消与提交所有权检查覆盖异步收尾。消息滚动逻辑提取到独立模块，流式更新按用户当前位置决定是否跟随底部。

## 6. 验证记录

侧栏在独立 Playwright 会话中加载实际页面模块，使用合成 Chrome API 和流式模型响应。已验证切页不发模型请求、页面正文与提问顺序、关闭开关、首条消息重开、读取时停止，以及流式更新下思考区与主消息区滚动位置保持。思考区 `scrollTop=120`、历史区 `scrollTop=160` 在追加内容后保持不变。另用真实 OPFS 文件夹句柄和 IndexedDB 验证首条消息转正式会话、模拟写盘失败进入 outbox、重开后恢复同步。没有调用真实模型。最终 `dist` 在独立本地预览服务中再次通过页面切换、停止、重开、滚动、输入框宽度、图标降级及排队消息测试；测试页面没有出现未处理异常。

界面按本次反馈去掉顶部页面卡片，只保留输入框内的页面来源行；不可读页面隐藏开关，网页图标优先使用标签页 favicon，失败时显示默认图标。
